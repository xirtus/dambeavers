## Rules

This is the **execution ledger**, not the full design document.

Statuses:


Only work on tasks whose prerequisites are DONE.

When a task is completed:

1. change its status to `REVIEW`,
2. run its acceptance tests,
3. run the independent critic pass,
4. fix substantive findings,
5. change it to `DONE`,
6. update notes with test evidence,
7. proceed to the next unblocked ID.

1. **Critical -- `War.endWar` crashed on a fully-contested loser claim.** The loser's claims are rewritten in place without their ceded cells, and `assertValidTerritoryClaim`'s former non-empty rule threw when a claim's cells were ALL contested -- a crash reachable from `tickPolitics.tickWars`. Also fixed `pickUp` itself to tolerate position-less items (nothing to clear). Regression kills the carrier twice across a re-issue with zero crashes.
3. **Moderate -- pickup `item-moved` events never named their carrier.** The dedupe expression compared the new carrier against ITSELF for cell-origin moves, so pickups recorded no participant (invisible to timelines and search). Fixed; regression proves the carrier appears in the event and in `entityTimeline`.
4. **Moderate -- collapse events always chained to the civilization's founding.** The precipitating-cause search looked for death events in `objectIds` naming the site -- a place a death event can never be (deaths don't name sites). Fixed to find the latest recent recorded population-loss event that DOES name the site (exodus, raid loot, world disaster); regression proves a real exodus becomes the collapse's recorded cause.
5. **Moderate -- inheritance-form succession ignored a dead leader's kin.** The rule read the dead leader's OWN relationship edges (destroyed with their components), silently falling back to highest-skill -- the exact case succession exists for. Fixed to read the edge from the surviving kin's side (edges are stored per-holder on both sides); regression proves the leader's child inherits over a more-skilled stranger.
6. **Minor -- a war's WINNER could be branded "displacement" by the cession they won.** The migration reason loop charged `territory-ceded` to anyone in its ids; the push-score rule correctly restricts it to the loser (subject). Fixed to mirror the push-score rule; regression proves the winner's exodus is never "displacement" from their own victory.

# Phase 9 — Wayfarer

Goal: allow the player to inhabit one creature inside the same simulated world. No separate adventure-world ruleset.

**Process note:** same batch-implementation approach as Phases 3-8 -- all 10 tasks implemented at pace into a new `src/sim/wayfarer/` layer, carried through the verification cycle retroactively: per-task acceptance tests against literal roadmap wording now EXIST for all 10 (`tests/simulation/p9-01-direct-creature-control-acceptance.test.ts` through `p9-10-return-to-colony-world-mode-acceptance.test.ts`), plus one consolidated smoke test (`tests/unit/phase9WayfarerSmoke.test.ts`, 4 end-to-end cases). Writing the tests surfaced and fixed REAL defects in this phase's own first drafts: (1) `tickControlledBeaver` counted a no-command tick as activity, so an idle controlled beaver accumulated fatigue; fixed (wasActive = a pending command actually executed). (2) The verb reachability rule required a 1-step path, but the navigator is 4-connected -- a diagonal neighbor is a real 2-step route and was wrongly unreachable; fixed to adjacency + genuine path existence. (3) `departSiteAsWayfarer` promoted only items the wayfarer PERSONALLY OWNED, silently leaving a stolen item held in hand behind at a site that was about to be deactivated; fixed to promote held-or-owned items, with held-but-not-owned items keeping their recorded legal owner (documented boundary semantics: names and recorded owners are the durable identifiers across the P6-08 scale boundary). (4) A blocked move command counted as activity; fixed. One deliberate additive refactor in existing machinery: `Battle.ts`'s exchange loop was extracted into an exported `resolveBattleExchange` (no behavior change; `tickBattle` calls it), so direct-control combat uses literally the same exchange a simulated battle uses; `Anatomy.ts`'s world-wide wound tick was extracted into an exported `tickCreatureWounds` (same); `BeaverNeeds.eatFoodItem`/`drinkWater` and `SocialInteraction.applyRelationshipContact` were exported (same primitives, new callers). Four new component types (player-control, wayfarer, wayfarer-link, companion) bring the registry 83 -> 87 (pinned count test bumped).
