# Dam Beavers — Everything Beyond the Systems Checklist

**Scope:** Do **not** duplicate the established ~300-item simulation/systems checklist. This is everything surrounding those systems that we need to reproduce, reinterpret, or exceed in order for **Dam Beavers** to have the breadth, continuity, usability, content density, and world-scale feeling of *Dwarf Fortress*.

---

## 1. Complete Game-Mode Architecture

*Dwarf Fortress* is not merely Fortress Mode. Its generated world is exposed through Fortress, Adventure, and Legends, with an object-testing arena as an additional environment.

* [ ] **Watershed Mode** — primary colony/civilization-management game
* [ ] **Adventure Mode equivalent** — control one individual in the same world
* [ ] **Chronicle Mode** — Dam Beavers equivalent of Legends
* [ ] **Object Testing / Simulation Arena**
* [ ] Shared world format between every mode
* [ ] Same characters appearing across modes
* [ ] Same artifacts appearing across modes
* [ ] Same ruins appearing across modes
* [ ] Same wars appearing across modes
* [ ] Same civilizations appearing across modes
* [ ] Same monsters appearing across modes
* [ ] Same historical events appearing across modes
* [ ] Ability to enter places previously controlled in Watershed Mode during Adventure Mode
* [ ] Ability to read Adventure events afterward in Chronicle Mode
* [ ] Ability for a player-created settlement to become part of world history
* [ ] Main-menu world browser
* [ ] World creation / loading / deletion
* [ ] Multiple active worlds
* [ ] Multiple settlements/adventures within one world's history
* [ ] World age displayed independently from playthrough age

# 46. The "Dam Beavers Test"

Every major feature should pass this test:

### **Could this event happen without a developer scripting the event itself?**

Bad:

> At population 100, trigger Dam Disaster quest.

Good:

> Materials deteriorate.
> Loads exist.
> Water pressure exists.
> Maintenance exists.
> Beavers make decisions.
> Structures can fail.

Therefore sometimes a dam disaster happens.

Likewise:

Bad:

> Script "pet accidentally gets drunk."

Good:

> Alcohol is a liquid.
> Containers break.
> Liquids spread.
> Animals drink accessible liquids.
> Alcohol affects nervous systems.

Therefore eventually something gets drunk.

That principle should govern the entire game.

# 47. The Three-Layer Identity of Dam Beavers

Everything should reinforce three interconnected worlds:

### **BANK**

Earth, burrows, mines, roots, caves, tombs, aquifers, underground industry.

### **WATER**

Rivers, lakes, ponds, dams, locks, canals, fisheries, transport, flooding.

### **CANOPY**

Forests, timber architecture, bridges, towers, elevated roads, tree cities.

Dwarf Fortress's iconic axis is overwhelmingly:

**DOWN.**

Dam Beavers' iconic axes become:

**DOWN + ACROSS + UP + WITH THE WATER.**

---

# 48. The Ultimate Parity Requirement

The final criterion isn't:

> "Does Dam Beavers have all the buttons Dwarf Fortress has?"

It is:

> **Can Dam Beavers generate stories with approximately the same causal depth, persistence, specificity and unpredictability—without needing those stories to be authored beforehand?**

And then exceed it through:

**hydrology + ecology + 3D physicality + centuries of visible environmental transformation.**

The resulting identity becomes:

> **Dwarf Fortress simulates civilization inside geology.**

> **Dam Beavers simulates civilization inside a living watershed.**

That is different enough to become its own thing while preserving the design philosophy that makes this genre extraordinary.
